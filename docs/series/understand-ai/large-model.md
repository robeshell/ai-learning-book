# 大模型究竟是什么

人们口中常说的大模型，通常指大语言模型（Large Language Model, LLM）。它是在海量文本上通过自监督学习预训练出来的深度神经网络，主流架构几乎全由 Transformer 构成。

它既不是懂得真伪的通识学者，也不是把海量网页存进硬盘的检索系统。你在任何一本公开文献里，都找不到一条所有人达成共识的最小参数分界线。学术界如 [Zhao 等人在 2023 年发表的综述](https://arxiv.org/abs/2303.18223) 中，通常把 100 亿（10B）参数作为讨论的基准线，但论文明确指出这只是观察到某些复杂推理能力后的经验划线。OpenAI 在 2020 年发布的 [GPT-3（Brown 等人）](https://arxiv.org/abs/2005.14165) 将公开可查的参数规模推到了 1750 亿，让大模型的规模效应真正进入公众视野。

大模型的物理实体是一份训练完成的权重文件。它在预训练阶段做的事情非常朴素：吞进海量无标注文本，把后面的内容遮住，让神经网络根据前面的文字去猜下一个词。猜得准，就顺着方向更新权重；猜得偏，就反向修正参数。

数万亿次循环计算之后，模型得到的不是一本随时翻阅的百科全书，而是一套对人类语言和世界概念高度压缩的统计关联矩阵。

把大模型当成已经拥有自我意识的智能体会走偏，把它贬为简单的复制粘贴同样看不清本质。它先掌握的是语言的统计规律：给定一段前置文本，它能算出词表里几万甚至几十万个候选词各自出现的概率，然后挑出合适的那个往下接。这套神经网络是如何计算上下文关联的，下一篇讲 Transformer；被模型读入和吐出的片段在机器底层长成什么样，第三篇讲 Token。

## 「大」指三项物理尺度的协同

大模型的「大」不是玄学概念，它明确对应三项可以度量的工程规模：参数量、训练数据量、消耗的计算量。少掉其中任何一项，所谓的大模型能力都无法成立。

<figure>
  <img src="/figures/large-model/scale.svg" alt="大模型的三维物理尺度" />
  <figcaption>大模型的三维物理尺度（参数、数据、算力）</figcaption>
</figure>

参数是神经网络里所有可学习的数值权重。训练结束后，这批浮点数会被固定在文件里。我们平时下载开源模型或者部署云端服务，核心承载物就是这份权重。参数越多，神经网络能容纳的表征空间和知识容量上限就越高。

数据是模型在预训练时读过的全部语料。网页、开源代码、图书文献、对话记录都会被洗净后送进模型。模型内部不存这些文本的原文，它把文字共现的统计规律提炼并沉淀在参数里。你让一个没有联网的模型复述某篇冷门论文的第 12 页第 3 行，它给出的文字读起来极其严谨，具体语句却往往和原著对不上。

算力是把海量数据和庞大参数结合起来做前向传播与反向传播所耗费的总计算。训练一个千亿规模的现代大模型，需要数千张乃至数万张高性能 GPU 在高带宽网络下持续协同运转数周或数月。没有算力支撑，再精巧的网络结构也无法在有效时间内收敛。

[Kaplan 等人在 2020 年发表的论文 *Scaling Laws for Neural Language Models*](https://arxiv.org/abs/2001.08361) 中指出了语言模型的标度律现象：在相当宽广的区间内，测试损失（Loss）随参数规模、数据规模和训练算力的增加呈现平滑的幂律下降。[Hoffmann 等人随后在 2022 年的 Chinchilla 实验](https://arxiv.org/abs/2203.15556) 中进一步给出了算力最优时参数与数据的配比。

规模效应说明了为什么把模型做大能显著提升生成质量和少样本泛化能力。但标度律优化的是下一词预测的损失函数，它没有承诺生成的句子在客观物理世界里一定属实。

后面我们会学到总参数很大、但每次计算只激活其中一小部分的混合专家模型（MoE）。阅读技术报告时要分清，有些数字标的是模型文件的总参数，有些标的是单次前向推理实际调用的激活参数，这两者是不同的概念。

## 一段话是一次一次接出来的

大模型无论是在数月漫长的预训练阶段，还是在服务用户的几秒钟推理过程中，底层运转的都是同一种机制：自回归（Autoregression）。

<figure>
  <img src="/figures/large-model/next-token.svg" alt="自回归循环生成机制" />
  <figcaption>自回归（Autoregression）循环生成机制</figcaption>
</figure>

自回归的运作方式是：模型接收当前已有的文本序列，计算出下一个最可能出现的词片段，把这个新片段拼接到原有文本末尾，然后再把更新后的长文本作为新的输入，重新送进模型计算。

这个过程像接龙一样循环往复，直到模型生成了代表结束的特定标记，或者达到了设定的长度上限。

```python
def autoregressive_generate(model, prompt_tokens, max_new_tokens=50):
    context = list(prompt_tokens)
    for _ in range(max_new_tokens):
        # 1. 传入当前完整上下文，计算下一个位置的词表概率分布
        logits = model(context)
        next_token = sample_from_logits(logits[-1])  # 按概率挑选候选词
        
        # 2. 如果抽中终止标记（EOS），结束生成
        if next_token == EOS_TOKEN:
            break
        # 3. 把新词追加到上下文末尾，作为下一轮输入
        context.append(next_token)
    return context
```

你在聊天界面看到的数百字连贯回答，在模型内部其实是一连串按先后顺序做出的局部概率采样。

例如当输入为「床前的月光照在」，模型在词表上计算候选分布：
- `地上`（72%）
- `窗台`（18%）
- `枕边`（8%）

模型根据采样策略选中「地上」后，输入立即被刷新为「床前的月光照在地上」，接着在下一轮循环中预测出逗号（`，`，91%），再下一轮预测出「静」（65%）……

<figure>
  <img src="/figures/large-model/sampling-flow.svg" alt="逐步概率采样与上下文追加流水线" />
  <figcaption>逐步概率采样与上下文追加流水线</figcaption>
</figure>

当你输入「人工智能的未来」，模型在预测第一个字时，脑子里并没有准备好第五百个字要写什么。它根据「人工智能的未来」，在词表上计算出「将」「在」「会」等候选词的概率分布。选出「将」之后，输入变成「人工智能的未来将」，再在此基础上预测下一个片段。

这种生成机制带来了一个不可避免的副产物：语句流畅与内容真实并不等价。

流畅性来自词汇在统计分布上的高频搭配。训练语料里大量优质文本让模型学会了主谓宾搭配、逻辑连词转换和专业术语用法。这种概率拟合能力，既可以生成完全符合事实的技术文档，也可以用同样笃定、优雅的句式生成荒谬绝伦的内容。

比如你问一个没有对齐知识库的基座模型：「周树人和鲁迅在 1927 年爆发过哪场学术论战？」模型可能会流畅写出：「1927 年春，周树人与鲁迅在北京大学就新文学规范展开了长达三小时的公开论辩，双方分别从白话文普及与古籍整理的角度……」从论点铺陈到语法结构无可挑剔，读起来极其严谨，但在物理事实层面完全是无稽之谈（鲁迅本名就是周树人）。

模型的优化目标是语言序列的统计连续性，它缺乏核查物理世界真伪的内在回路。我们在第 7 篇会展开采样温度和概率截断如何影响词汇选择，第 10 篇则会专门拆解幻觉的物理本质。

## 产品、模型、基座要分开看

很多时候人们对大模型能力的困惑，来自没有把产品、对齐模型和预训练基座这三层结构区分开。

<figure>
  <img src="/figures/large-model/layers.svg" alt="AI 系统三层架构" />
  <figcaption>AI 系统三层架构（产品层、对齐模型、基座权重）</figcaption>
</figure>

最顶层是产品与应用层。以 2022 年 11 月上线的 [ChatGPT（OpenAI 官方公告）](https://openai.com/index/chatgpt/) 为例，它是一个完整的互联网应用。产品层负责处理用户账号、前端交互、历史会话持久化，在用户输入前悄悄拼接系统提示词（System Prompt），在输出端配置内容安全审查策略，并在需要时触发搜索引擎或代码执行沙箱。

中间层是对齐模型（Instruct / Chat Model）。如果把刚训练完的原始基座直接推到前端，它通常无法胜任助手工作——你问它「北京今天天气怎么样」，它可能顺着你的句式接龙写出「上海今天天气怎么样，广州今天天气怎么样」。对齐模型是在基座模型的基础上，通过指令微调（SFT）和人类偏好对齐（RLHF 或 DPO）进一步训练出来的。经过这一道工序，权重才学会了扮演一个听得懂指令、愿意提供解答、知道在触碰安全红线时礼貌拒答的助手。

最底层是预训练基座模型（Base Model）。它是用数万亿语料自监督跑出来的毛坯权重。所有上层的指令理解、逻辑推导和风格定制，都以基座里沉淀的统计知识为基础。

我们可以通过一个具体的场景来看清三层的差异：假设你在输入框发送了一条指令：`写一个生成 16 位强随机密码的 Python 脚本`。

- **底层基座模型**：把它当作一段未完待续的网络论坛帖子或作业题在续写。它可能会顺着句式接龙输出：`2. 写一个用正则表达式校验邮箱有效性的脚本；3. 写一个……`；
- **中层对齐模型**：理解了这是用户在寻求编程帮助，直接输出符合意图的解答：`好的，可以使用 Python 内置的 secrets 模块来实现：...`；
- **顶层产品层**：在将输入送给模型前，先拼上 System Prompt 规定身份风格，输出时在前端渲染带有语法高亮和「一键复制」按钮的代码卡片，并在发现恶意代码请求时由风控模块在底层模型运算前直接拦截。

把这三层分清，在日常使用和技术选型时能省去大量无谓的误判：

你在网页端使用一个对话产品，发现它的输出风格变了，或者突然拒绝回答某类问题，往往不是底层模型被换掉了，可能只是产品层调整了隐藏的 System Prompt，或者收紧了风控拦截规则。

你通过 API 直接调用模型，拿到的结果通常更接近模型权重本身的反应，但不同服务商依然可能在 API 背后做隐式封装。开源社区里发布的 Base 版和 Instruct 版，区别就在于有没有走完中层的对齐工序。

「我在用某某聊天软件」指的是产品，「我在调用某个版本的对齐权重」指的是经过微调的模型，「这个基座支持多大上下文」指的是最底层的原始架构。谈论大模型时，把这三个对象放在各自的层面上看，后面的计费、安全注入、工具调用与智能体系统才能理得顺。

## 读到这里该能分清

大模型是在海量无标注文本上预训练的自回归神经网络，主流骨干是 Transformer。

「大」指参数容量、语料数据和训练算力三项工程规模，不是超越物理规律的神秘意识。

大模型生成文本依赖自回归概率预测。它一步步挑选在统计上合理接续的片段，流畅表达不等于事实核验。

AI 系统分为产品应用、对齐模型与预训练基座三层。每一层承担不同的工程职责，各自决定不同的行为边界。

下一篇我们进入模型的内部结构，拆解 Transformer 为什么能并行计算词语之间的关系，以及 Q、K、V 是如何协同工作的。第三篇则会把模型接收和输出的语言片段，落到具体的 Token 机制上。
