# 什么是 Transformer

上一篇把今天常见大模型的主干点到 Transformer。它不是一个会思考的模块。Vaswani 等人 2017 年在 *Attention Is All You Need* 里提出这套结构：层与层之间不再靠循环或卷积传递，注意力本身承担位置之间的关系。

原论文做的是机器翻译，结构是编码器加解码器。今天用来聊天的模型，常常只留下解码器这一侧。内部那一层自注意力，仍是同一套算法。

## 循环网络为什么会被换掉

循环网络按位置往下传。位置 2 必须等位置 1 的隐状态算完，位置 3 再等位置 2。句子一长，开头和末尾要绕过整段中间。论文 Table 1 把这件事写成数字：循环层最少要做 O(n) 步顺序计算，任意两位置的最长路径也是 O(n)。

自注意力换了一种接法。同一层里，任意两个位置以常数步数相连。最少顺序步数是 O(1)。训练时，整句可以一起送进矩阵运算，不必在时间步上排队。GPU 擅长这种一次铺开的乘法，不擅长「算完这个才能算下一个」。这是它能换掉循环网络的原因。不是因为它更「懂句子」。

  <figcaption>换掉循环，首先是为了减少必须串行的步数，让远距离不必绕整句传递。</figcaption>
</figure>

Google 研究博客用过一句英文例子：I arrived at the bank after crossing the river。要判断 bank 是河岸还是银行，循环网络得把「河」一路传到后面。自注意力可以让 bank 这一步直接去看 river。原论文在 WMT 2014 英法翻译上，用 8 块 GPU 训练 3.5 天达到 41.0 BLEU，并把它写成可并行、训练时间更短的证据。数字说明的是算得动，不是模型已经理解世界。

## 自注意力在算什么

自注意力的对象是同一条序列。每个位置更新自己的表示时，会对序列里其他位置打分，再按分数把它们的信息混合进来。所有配对可以一次算完，所以叫并行。

<figure>
  <img src="/figures/transformer/self-attention.svg" alt="从左到右：这个位置，对全句打分，按分数混合成新向量。" />
  <figcaption>每个位置并不是先读完再思考。它是对全句打分，再按分数混合。</figcaption>
</figure>

解码器还要遵守上一篇说的自回归。写到「今天天气」时，后面那个还没选出来的片段必须看不见，否则模型会偷看答案。实现上，非法位置在 softmax 之前被打成负无穷，权重变成零。编码器翻译源句时可以看整句。解码器生成时只看已经出现的部分。两套规则不要混。

位置之间怎么编号、文字怎么切成片段，下一篇讲 Token。没有位置信息，注意力会把序列当成一袋可以任意对调的向量。位置编码怎么加，本篇不展开。这里只需记住：注意力操作的是已经变成向量的序列，不是人类眼睛里的「字」。

## Q、K、V 是三种投影

Query、Key、Value 听起来像三座仓库。它们不是。同一组输入，经过三种不同的线性投影，得到三种用法。

Query 回答：这个位置在找什么。Key 回答：那个位置如何被对上。Value 回答：对上之后真正拿出来混合的是什么。打分发生在 Query 和 Key 之间。混合发生在 Value 上。

<figure>
  <img src="/figures/transformer/qkv.svg" alt="三张卡片分别是 Query、Key、Value，对应寻找、对上、取出。" />
  <figcaption>Q、K、V 是同一组输入的三种投影。找和对是一回事，拿出来是另一回事。</figcaption>
</figure>

计算上，先把 Query 和所有 Key 做点积，再除以 √d_k，然后 softmax。除以根号是为了避免点积随维度变大，把 softmax 挤进极端区间。Vaswani 等人把这个形式叫做缩放点积注意力。公式可以记成 Attention(Q, K, V) = softmax(QKᵀ / √d_k) V。读到能对上上面那句话即可，不必在这里展开矩阵推导。

## 多头，以及为什么长度一涨就贵

单头注意力会把不同关系平均掉。句法上的邻接、指代上的远距离对齐，挤在一路里容易互相冲掉。多头把 Q、K、V 再投影几次，并行做几路注意力，再拼回去。原论文用 8 个头，模型宽度 512，每头 64 维。头变多，不是变聪明的口号，是让不同子空间各算各的关系。论文写过：单头的平均会抑制这种分工。

代价写在另一侧。自注意力一层要为 n 个位置两两打分，复杂度是 O(n² · d)。循环层是 O(n · d²)。论文写明：当 n 小于表示维度 d 时，自注意力通常更快。翻译句子常常满足这个条件。序列一拉长，n² 个分数会反过来成为负担。不必把公式背下来。记住一件事即可：长度变成两倍，配对分数大约变成四倍。这就是后面讲上下文窗口时，长度不能无限加的结构原因。

<figure>
  <img src="/figures/transformer/heads-and-cost.svg" alt="左侧是多头并行再拼接，右侧是 n 个位置对应 n 乘 n 个分数。" />
  <figcaption>多头解决的是「一种平均会抹掉关系」。平方代价解释的是「为什么特别长的序列会变贵」。</figcaption>
</figure>

本篇只讲到能用的程度。残差、归一化、前馈层、位置编码怎么加，不在这里展开。现行某代模型有多少层、多少头，没有公开出处的数字，不写。

## 读到这里该能分清

Transformer 用自注意力在一层里连接序列中的位置，从而减少必须串行的步数。每个位置对全句打分再混合。Q、K、V 是三种投影，不是三座库。多头保住不同子空间。n² 个分数决定了长度涨上去会变贵。
