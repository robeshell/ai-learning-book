# 概念长文撰写流程规范（write-article Skill）

当需要撰写或重构某一篇文章时，必须严格按照以下步骤执行，不得跳步：

## 阶段一：目标定位、文献检索与事实证据链（Research & Grounding）
1. 读取 `docs/.vitepress/series.ts` 中该文章的条目定义（`id`, `title`, `description`, `points`, `prerequisites`）。
2. **显式调研与证据链检索**：
   - 检索该主题的经典论文（arXiv / 顶会）、工业界主流开源实现（vLLM、SGLang、DeepSpeed 等）及官方技术白皮书。
   - 提取并核验真实 Benchmark 数据、数学推导公式与核心算法机制。
   - 整理并向用户呈现《前置事实与调研报告》（包含核心论点依据、将引用的论文列表、通俗生活比喻设计与图表构思），确保事实链路完全透明可查。
3. 经确认后进入后续阶段。

## 阶段二：矢量图表与动画制作（SVG & Manim）
1. 在 `docs/public/figures/<article-id>/` 目录下生成 2~4 张配套图表/动画（通常为 3 张）：
   - 全景流水线 / 宏观架构图（如 `architecture.svg` / `pipeline.svg`）
   - 算法细节 / 微观机制图（如 `mechanism.svg` / `comparison.svg`）
   - 工业权衡 / 现实认知桥梁图（如 `tradeoff.svg` / `grounding-bridge.svg`）
   - 复杂动态过程可使用 Manim 渲染生成 WebM/MP4 短视频动画。
2. **文字安全边界约束**：
   - 必须严格计算卡片容器宽度与文本字符长度；
   - 预留 20px+ 安全内边距，严禁文本贴边或超出容器边界；
   - 统一遵循 Kami 设计系统配色（主色 `#1b365d`，强调色 `#2563eb`，背景 `#f8fafc` / `#ffffff`，边框 `#cbd5e1`）。
3. **图题与说明文字（Figcaption）规范**：
   - `<figcaption>` 必须控制在 **10~25 字以内的极简短语**，仅做结构索引和主题标识；
   - 严禁在 `<figcaption>` 中复制、复述正文大段原话或背景解释。

## 阶段三：正文撰写（严格遵循分层认知漏斗与 7 步骨架）
1. **Frontmatter**：保留完整的元数据字段，`articleStatus` 设为 `draft`。
2. **一级标题与生活化引言**：用 2~3 段通俗生活场景/痛点切入，点明概念本质，插入全景图（`<figure>` + 极简 `<figcaption>`）。
3. **痛点与因果演进**：梳理历史方案局限，用大白话讲清楚为什么必须发明这项技术。
4. **技术细节与极简代码卡片**：
   - 配合细节机制图，用通俗语言拆解算法流程；
   - 公式紧随大白话参数释义，杜绝学术代号劝退；
   - 提供 15~30 行极简、高可读性的 Python 核心逻辑代码，附带中文逐行注释与输入输出打印。
5. **现实权衡与奇特表象剖析**：解释 1~2 个由底层物理/算法机制引发的工业现实痛点（如「为什么显存装不下」、「汉字刺客」等）。
6. **`## 读到这里该能分清`**：4~5 条通俗精炼的核心认知要点总结 + 承上启下引出下一篇主题。
7. **`## 参考文献`**：1~5 篇权威论文 / 官方技术报告，包含作者、年份、斜体标题和有效超链接。

## 阶段四：元数据同步与全站校验
1. 将 `docs/.vitepress/series.ts` 中对应文章的 `articleStatus` 同步更新为 `draft`。
2. 执行自动化校验脚本 `npm run verify` 与全站静态构建 `npm run build`，确保零格式错误与零坏链。
